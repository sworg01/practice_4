## 1. Чим змінна відрізняється від масиву

**Змінна** — це іменована область пам’яті або програмна сутність, що використовується для зберігання значення певного типу.

**Масив** — це структура даних, яка містить фіксовану кількість елементів одного типу. Кожен елемент має свій індекс, за яким до нього можна звернутися.

Основні відмінності:

- Змінна зберігає одне значення, а масив — набір елементів.
- До змінної звертаються за її ім’ям, а до елемента масиву — за ім’ям масиву та індексом.
- Тип звичайної змінної визначає тип одного значення, а тип масиву — тип усіх його елементів.
- Розмір масиву після створення змінити неможливо.

```java
int number = 10;

int[] numbers = {10, 20, 30};

System.out.println(number);      // 10
System.out.println(numbers[1]);  // 20
```

## 2. Що таке стек? Що таке купа? Яка між ними різниця?

**Стек (stack)** — це область пам’яті, яка використовується для організації викликів методів, зберігання їхніх локальних змінних і проміжних даних виконання. Кожен потік виконання Java має власний стек.

**Купа (heap)** — це область пам’яті, у якій розміщуються об’єкти та масиви, створені під час виконання програми. Пам’ять у купі автоматично звільняється збирачем сміття (Garbage Collector), коли об’єкти більше не доступні з програми.

Основні відмінності:

- Стек використовується для обслуговування викликів методів, а купа — для зберігання об’єктів і масивів.
- Кожен потік має власний стек, тоді як купа є спільною для потоків у межах JVM.
- Пам’ять стека звільняється під час завершення відповідних викликів методів, а пам’ять купи може бути звільнена збирачем сміття.
- Стек має обмежений розмір, а купа зазвичай значно більша.

Конкретне розміщення окремих значень і реалізація пам’яті залежать від JVM та оптимізацій компілятора.

## 3. Чи може змінна бути розташована у стеку, безпосередньо у купі, в об’єкті у купі? Чи може масив бути розташований у стеку, безпосередньо у купі, в об’єкті у купі?

У Java необхідно розрізняти саму змінну, її значення та об’єкт, на який вона може посилатися.

- **У стеку:** локальні змінні та параметри методів можуть зберігатися у стекових кадрах або оптимізуватися JVM. Примітивна локальна змінна містить значення, а змінна-посилання — посилання на об’єкт.
- **Безпосередньо у купі:** окремі звичайні локальні змінні не створюються в купі як самостійні об’єкти. Проте об’єкти та масиви розміщуються в купі за стандартною моделлю Java.
- **В об’єкті у купі:** поля об’єкта розташовані як частина його стану. Примітивне поле містить значення, а поле-посилання — посилання на інший об’єкт.
- **Масив у стеку:** за стандартною моделлю масив є об’єктом, тому його елементи не є окремим локальним масивом у стеку. JVM може оптимізувати фізичне розміщення за умови збереження поведінки програми.
- **Масив безпосередньо у купі:** так, масив є об’єктом і за стандартною моделлю розміщується в купі.
- **Масив в об’єкті у купі:** об’єкт може містити поле-посилання на масив. Сам масив при цьому є окремим об’єктом.

```java
class Example {
    int number = 10;
    int[] values = {1, 2, 3};
}

public class Main {
    public static void main(String[] args) {
        int localNumber = 5;
        int[] localArray = {10, 20, 30};

        Example example = new Example();
    }
}
```

У цьому прикладі `localNumber` і `localArray` — локальні змінні, а `Example`, масиви та їхні елементи належать до об’єктів відповідно до моделі Java.

## 4. Чим посилання на масив відрізняється від масиву? Чи може посилання на масив бути розташовано у стеку, безпосередньо у купі, в об’єкті у купі?

**Масив** — це об’єкт, який містить елементи певного типу.

**Посилання на масив** — це значення, за допомогою якого програма може звертатися до відповідного об’єкта масиву.

Посилання не є самим масивом. Кілька змінних можуть посилатися на один і той самий масив.

- **У стеку:** локальна змінна-посилання може бути частиною стекового кадру методу.
- **Безпосередньо у купі:** посилання може бути значенням поля іншого об’єкта або елементом масиву посилань. Самостійним об’єктом посилання не є.
- **В об’єкті у купі:** поле об’єкта може містити посилання на масив.

```java
int[] first = {1, 2, 3};
int[] second = first;

second[0] = 100;

System.out.println(first[0]); // 100
```

У цьому прикладі `first` і `second` посилаються на один масив. Зміна його елемента через одне посилання відображається і при зверненні через інше.

## 5. Якщо масив складається з 10 комірок, які індекси мають перша та остання комірки?

У Java індексація масивів починається з нуля.

Якщо масив містить 10 елементів:

- Індекс першої комірки — `0`.
- Індекс останньої комірки — `9`.

Загальна формула останнього індексу:

```java
array.length - 1
```

Приклад:

```java
int[] array = new int[10];

System.out.println(array[0]);                 // перший елемент
System.out.println(array[array.length - 1]);  // останній елемент
```

## 6. Що буде, якщо звернутися до неіснуючої комірки у масиві?

Якщо звернутися до елемента за індексом, який виходить за межі масиву, Java викине виняток **`ArrayIndexOutOfBoundsException`**, що є підкласом `IndexOutOfBoundsException`.

Наприклад:

```java
int[] array = {10, 20, 30};

System.out.println(array[3]);
```

У цьому випадку виникне виняток, оскільки допустимі індекси — від `0` до `2`.

Якщо виняток не перехоплено, виконання поточного потоку завершиться аварійно.

## 7. Як ініціалізуються елементи нового масиву без явної ініціалізації?

Під час створення нового масиву в Java всі його елементи автоматично отримують **значення за замовчуванням**, а не довільні значення, які могли бути в пам’яті раніше.

Значення залежать від типу елементів:

- Числові примітивні типи (`byte`, `short`, `int`, `long`) — `0`.
- Типи з рухомою комою (`float`, `double`) — `0.0`.
- Тип `char` — символ `'\u0000'`.
- Тип `boolean` — `false`.
- Посилальні типи, зокрема `String` та інші об’єкти, — `null`.

Приклад:

```java
int[] numbers = new int[3];
boolean[] flags = new boolean[2];
String[] names = new String[2];

System.out.println(numbers[0]); // 0
System.out.println(flags[0]);   // false
System.out.println(names[0]);   // null
```

## 8. Як дізнатися номер першої та останньої комірки масиву, якщо відомо лише посилання на нього?

Якщо є посилання на масив, кількість його елементів можна дізнатися через властивість `length`.

- Індекс першої комірки завжди дорівнює `0`, якщо масив не порожній.
- Індекс останньої комірки дорівнює `array.length - 1`.
- Якщо масив порожній, його довжина дорівнює `0`, тому першого й останнього елементів немає.
- Якщо посилання дорівнює `null`, звернення до `length` призведе до `NullPointerException`.

Приклад:

```java
int[] array = {10, 20, 30, 40};

System.out.println("Перший індекс: 0");
System.out.println("Останній індекс: " + (array.length - 1));
```

Результат:

```text
Перший індекс: 0
Останній індекс: 3
```

## 9. Як змінити розмір масиву?

У Java розмір масиву **не можна змінити після його створення**. Щоб отримати масив іншого розміру, потрібно створити новий масив і, за необхідності, скопіювати в нього елементи старого.

Приклад:

```java
import java.util.Arrays;

int[] array = {1, 2, 3};

array = Arrays.copyOf(array, 5);

System.out.println(Arrays.toString(array));
```

Результат:

```text
[1, 2, 3, 0, 0]
```

Метод `Arrays.copyOf()` створює новий масив заданого розміру та копіює доступні елементи. Якщо новий масив більший, додаткові комірки отримують значення за замовчуванням.

Якщо потрібна структура, розмір якої змінюється автоматично, можна використовувати `ArrayList`.

## 10. Що відбувається з масивом при копіюванні посилання на нього?

Під час копіювання посилання копіюється не сам масив, а значення посилання. У результаті обидві змінні посилаються на той самий об’єкт масиву.

Зміни елементів через одне посилання будуть видимі через інше.

```java
int[] first = {1, 2, 3};
int[] second = first;

second[1] = 99;

System.out.println(Arrays.toString(first));
```

Результат:

```text
[1, 99, 3]
```

Щоб отримати незалежну копію масиву, потрібно скопіювати його елементи, наприклад за допомогою `Arrays.copyOf()`.

## 11. Що відбувається з масивом при втрачанні посилання на нього?

Якщо на масив більше не існує доступних посилань із коренів досяжності JVM, він стає **недосяжним об’єктом**.

Такий масив може бути видалений збирачем сміття (Garbage Collector), який звільнить зайняту ним пам’ять.

Однак видалення відбувається не обов’язково одразу після втрати посилання. Час збирання сміття визначається JVM.

Приклад:

```java
int[] array = {10, 20, 30};

array = null;
```

Після присвоєння `null` змінна `array` більше не посилається на створений масив. Якщо інших доступних посилань на нього немає, масив стає кандидатом на збирання сміття.

## 12. Чим відрізняються конструкції `for` та `for-each` при роботі з масивами? Які переваги та недоліки кожного варіанта?

**Цикл `for`** — це цикл із лічильником, у якому можна керувати початковим значенням, умовою завершення та кроком.

```java
int[] numbers = {10, 20, 30};

for (int i = 0; i < numbers.length; i++) {
    System.out.println("Індекс: " + i + ", значення: " + numbers[i]);
}
```

Переваги `for`:

- Можна отримати індекс поточного елемента.
- Можна змінювати порядок обходу масиву.
- Можна пропускати елементи або обробляти лише певні індекси.
- Можна змінювати значення елементів масиву за індексом.

Недоліки `for`:

- Потрібно самостійно правильно задавати межі циклу.
- Є ризик помилитися з індексом і отримати `ArrayIndexOutOfBoundsException`.
- Код може бути довшим.

**Цикл `for-each`** — це спрощена конструкція для послідовного обходу елементів масиву або іншої колекції.

```java
int[] numbers = {10, 20, 30};

for (int number : numbers) {
    System.out.println(number);
}
```

Переваги `for-each`:

- Код коротший і простіший для читання.
- Не потрібно вручну керувати індексами.
- Зручно використовувати, коли необхідно обробити кожен елемент.

Недоліки `for-each`:

- Не надає безпосереднього доступу до індексу поточного елемента.
- Незручно обходити масив у зворотному порядку.
- Не можна безпосередньо змінити елемент масиву через змінну циклу, якщо елемент має примітивний тип.

Наприклад:

```java
int[] numbers = {1, 2, 3};

for (int number : numbers) {
    number = 0;
}

System.out.println(Arrays.toString(numbers)); // [1, 2, 3]
```

У цьому прикладі змінюється лише локальна змінна `number`, а не елементи масиву. Для зміни елементів потрібно використовувати `for` з індексом.

## 13. Чи можна у масив `double[]` записати значення `int`? Чи можна у масив `int[]` записати значення `double`?

**У масив `double[]` можна записати значення типу `int`.** Java автоматично перетворює `int` на `double`, оскільки це розширювальне числове перетворення.

```java
double[] values = new double[3];

values[0] = 10;

System.out.println(values[0]); // 10.0
```

**У масив `int[]` не можна безпосередньо записати значення типу `double`.** Таке присвоєння призведе до помилки компіляції, оскільки перетворення з `double` на `int` може призвести до втрати дробової частини.

```java
int[] values = new int[3];

// values[0] = 10.5; // Помилка компіляції

values[0] = (int) 10.5;

System.out.println(values[0]); // 10
```

Для запису значення `double` у `int[]` потрібно виконати явне перетворення типу `(int)`. Під час такого перетворення дробова частина відкидається в напрямку нуля, а не округлюється до найближчого цілого числа.
